# Подключение VOT к своему Universal Media Proxy

Эта инструкция предназначена для пользователя, который хочет **изменить исходный код своего VOT**, собрать расширение/userscript и направить перевод, аудио и субтитры через **собственный сервер**. Поддерживаемая версия VOT должна иметь клиент `VOTClient` с методами `request()` и `getOpts()`; в других версиях названия и структура могут отличаться.

> **Важно:** готовый ZIP содержит сервер и пример клиентского TypeScript-кода, **но не содержит готовой сборки VOT**. Подмена одного URL в обычном VOT не гарантирует работу: сервер ожидает protobuf-envelope. Пример клиента нужно встроить в конкретный исходный код VOT и пересобрать.

## Шаг 1. Запустите свой сервер

1. Разместите проект на VPS с Node.js 22+ или запустите `sudo bash install.sh` на поддерживаемой системе. Прочитайте скрипт до запуска: он меняет системные службы и может заменять конфигурацию Caddy.
2. Настройте домен и HTTPS (например, `proxy.example.com`). DNS должен указывать на VPS; порты 80/443 должны быть доступны.
3. В окружении сервера установите `ENABLE_VOT_PROXY=true`, `PUBLIC_BASE_URL=https://proxy.example.com`, секрет `TOKEN_SECRET` и другие параметры из `.env.example`. Для установки через скрипт настройки могут храниться в `/etc/universal-media-proxy.env`.
4. Перезапустите службу и проверьте:

```bash
curl -i https://proxy.example.com/health
```

Ожидайте успешный HTTP-ответ от вашего сервера. **Не проверяйте VOT отправкой произвольного пустого POST**: ошибка 400/405 не доказывает, что маршрутизация сломана.

## Шаг 2. Подготовьте исходники VOT

Откройте исходники вашей версии VOT. Приведённые ниже пути проверялись для одного из форков; если пути отличаются, ищите по названиям символов.

| Что найти | Пример пути | Изменение |
| --- | --- | --- |
| `TranslateProxyStatus` | `src/types/storage.ts` | Добавить режим `3` |
| `proxyEnabledLabels` | `src/components/Settings/SettingsProxySection.tsx` | Добавить пункт «Свой сервер (protobuf)» |
| `buildVOTClient()` | `src/VideoHandler.ts` | Для режима `3` выбрать новый провайдер |
| `isProxyRoutingEnabled` | `src/videoHandler/modules/proxyShared.ts` | Включить режим `3` для аудио и субтитров |
| `resolveProxyWorkerHost` | Поиск по проекту | Не допускать двойного `https://` или `/vot/vot` |
| `PROXY_MODES` | `src/modules/telemetry/context.ts` | Добавить название четвёртого режима |

Подробности и ограничения — в [полной инструкции](VOT_CODE_CHANGES_RU.md).

## Шаг 3. Добавьте клиент protobuf-envelope

Скопируйте [reference/protobufEnvelopeProvider.ts](reference/protobufEnvelopeProvider.ts) в подходящий каталог вашего VOT и **исправьте относительный импорт** `VOTClient` под вашу структуру. Пример экспортирует `VOTProtobufEnvelopeClient`.

В `buildVOTClient()` импортируйте этот класс и выберите его для режима `3`:

```ts
provider: this.data?.translateProxyEnabled === 3
  ? VOTProtobufEnvelopeClient
  : proxyClientEnabled ? VOTNextWorkerProvider : YandexProvider,
```

**Не заменяйте** этим клиентским `.ts` серверный `src/vot-worker.js`. Клиент упаковывает исходное тело, допустимые заголовки и внутренний путь в protobuf-envelope; сервер распаковывает его и отправляет запрос далее. Подписанные заголовки и управление сессией должны оставаться рабочими.

Для Bilibili образец дополнительно передаёт URL открытого видео, если путь `/video-translation/translate` и страница соответствует Bilibili. Для иных сайтов проверьте требования их адаптера.

## Шаг 4. Настройте URL прокси в VOT

Для домена `proxy.example.com` фактический запрос должен уходить на:

```text
https://proxy.example.com/vot/video-translation/translate
```

В **проверенном форке** поле хоста ожидает адрес **без протокола**, например:

```text
proxy.example.com/vot
```

Если ваш форк принимает полный URL, укажите `https://proxy.example.com/vot` и адаптируйте `resolveProxyWorkerHost`. **Не добавляйте `/vot` дважды.** Внутри protobuf-envelope путь должен оставаться `/video-translation/translate`, без внешнего `/vot`.

Выберите в настройках VOT новый режим «Свой сервер (protobuf)».

## Шаг 5. Разрешите сетевой доступ и соберите VOT

- Userscript: разрешите `@connect proxy.example.com` в метаданных.
- Расширение: проверьте `host_permissions`, фоновые запросы и CORS с учётом архитектуры сборки.
- Выполните проверку типов и сборку согласно `package.json` **вашего** VOT (в проверенном форке использовались `bun run check` и `bun run build:gm`).
- Установите собранную версию в браузер, откройте поддерживаемое видео и запустите перевод.

## Шаг 6. Проверьте работу

В DevTools → Network найдите:

```text
POST https://proxy.example.com/vot/video-translation/translate
Content-Type: application/x-vot-envelope+protobuf
```

Затем проверьте запросы к аудио/субтитрам через ваш домен и воспроизведение перевода. `/health` подтверждает доступность сервера, **но не успешную работу Яндекса или Bilibili**.

| Симптом | Что проверить |
| --- | --- |
| Запрос идёт прямо к Яндексу | Выбран ли режим `3`, вызывается ли новый провайдер |
| `404` | Домен, путь `/vot/...`, двойной `/vot` |
| `400` | Тип `application/x-vot-envelope+protobuf`, тело, путь внутри envelope, заголовки |
| `401`/`403` | Доступ к серверу, ограничения инфраструктуры, права/подписи upstream; публичная версия прокси не требует `X-Proxy-Key` |
| `402` | Смотрите серверные логи и ответ upstream; причина не установлена по одному статусу |
| Ошибка CORS/permissions | `@connect`, `host_permissions`, политика расширения, HTTPS |
| Перевод есть, звука нет | Проксирование аудио, URL `/media/...`, Range/206, разрешённые CDN-хосты |
| Работает только один сайт | `matches`/`prepareMediaTranslation` соответствующего адаптера и журналы сервера |

## Безопасность

Не публикуйте `TOKEN_SECRET`, заголовки сессии и подписанные ссылки. Открытый `/vot` может потреблять ресурсы VPS и использоваться посторонними; настройте HTTPS, лимиты запросов и контроль доступа на уровне инфраструктуры. Не вставляйте секрет сервера в публичный userscript. Учтите условия использования сайтов и сервисов перевода.

## Что нельзя обещать заранее

Пример TypeScript-клиента и патч относятся к конкретному форку VOT; интеграция с другой версией может потребовать дополнительных изменений. Автоматические тесты сервера не заменяют тесты реального перевода, сессий и аудио в браузере.
