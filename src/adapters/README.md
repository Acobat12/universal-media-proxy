# Подключение нового сайта

Создайте файл `src/adapters/example.js` непосредственно в этой папке и перезапустите Node.js. Загрузчик игнорирует скрытые файлы и файлы `.bak`. Если адаптер содержит ошибку, запуск сервера остановится с сообщением об ошибке: неисправный адаптер не будет незаметно пропущен.

```js
export default {
  id: 'example',
  // Доверенные домены CDN: без протокола, пути и подстановочных знаков.
  mediaHosts: ['cdn.example.com'],
  matches(url) {
    return url.protocol === 'https:' && url.hostname === 'example.com' && url.pathname.startsWith('/video/');
  },
  async resolve(url, { fetcher, quality, signal }) {
    // Реализуйте получение медиа через доступный API сайта.
    // Не запрашивайте произвольные URL и учётные данные пользователя.
    return {
      site: 'example', id: url.pathname.split('/').pop(),
      contentType: 'audio/mp4',
      upstreams: ['https://cdn.example.com/path-to-real-media.mp4'],
      headers: {}, metadata: { quality }
    };
  }
};
```

Домены из `mediaHosts` автоматически добавляются в список разрешённых CDN. Указывайте только доверенные публичные домены. Медиаадреса дополнительно проверяются: требуется HTTPS, а DNS-адрес не должен указывать на внутреннюю сеть. Вместо `mediaHosts` можно настроить переменную окружения `ALLOWED_UPSTREAM_HOSTS`. Список загруженных адаптеров доступен через `GET /health`.

**Важно:** общий маршрут `/api/resolve` использует все зарегистрированные адаптеры. Обработка protobuf и постоянные медиаадреса Bilibili, а также регистрация видео и специальные маршруты Douyin реализованы отдельно в соответствующих адаптерах. Добавление обычного адаптера само по себе не создаёт специальные интеграции и не обходит авторизацию или DRM.

### Обработка запросов перевода VOT

Адаптер может дополнительно реализовать `async prepareMediaTranslation(body, { publicBaseUrl })`. Если подписанный запрос относится к этому сайту, метод возвращает `{ body, mediaUrl }`. Если запрос относится к другому сайту, метод возвращает `null`.

Общий диспетчер проверяет адаптеры по убыванию `mediaTranslationPriority` (по умолчанию `0`). Не изменяйте байты подписанного запроса, если используемая схема подписи явно этого не допускает. Логика перевода, зависящая от сайта, должна находиться в адаптере, а не в `src/media-translation.js`.

### Правила выбора адаптера для VOT

Метод `prepareMediaTranslation(body, context)` должен возвращать `null` для запросов других сайтов. Возвращайте `{ body, mediaUrl }` при успешной обработке, а ошибку выбрасывайте только тогда, когда запрос точно относится к вашему адаптеру, но имеет неверный формат. Это позволяет подключать дополнительные сайты без изменений `media-translation.js`. Адаптеры с более высоким `mediaTranslationPriority` проверяются первыми.

## Постоянные URL без токенов

Чтобы адаптер работал через `POST /api/resolve` и `GET /media/<site>/...`, добавьте:

```js
stableMediaPath(url, { quality }) {
  // Верните постоянный безопасный путь с проверенным идентификатором.
  return `/media/newsite/${extractAndValidateId(url)}/audio.mp4`;
},
async resolveMediaPath(path, { fetcher, signal }) {
  // Проверьте весь путь и восстановите канонический URL видео
  // и вызовите this.resolve(...). Никаких URL от клиента для CDN.
  const id = parseAndValidateMediaPath(path);
  return this.resolve(new URL(`https://newsite.example/watch/${id}`), { fetcher, signal });
}
```

Не используйте случайные токены, временные URL CDN или пользовательские upstream-адреса как постоянные идентификаторы. Bilibili реализует эти методы. Douyin использует собственный маршрут с регистрацией идентификатора видео; регистрация хранится в памяти и требует повторения после перезапуска. Для нового сайта эти методы не добавляются автоматически.


## Обязательные части интеграции нового сайта: серверный адаптер + VOT Helper + транспорт

**Серверный адаптер не равен клиентскому Helper.** Файл `src/adapters/<site>.js`
в Universal Media Proxy регистрируется загрузчиком серверных адаптеров. Он отвечает
за разрешение медиа, доверенные CDN, постоянные URL и, при необходимости,
`prepareMediaTranslation()`. Сам по себе он **не добавляет поддержку сайта в VOT**.

**Клиентский Helper** добавляется в исходники форка VOT по образцу
[`docs/reference/bilibili-helper-user-example.js`](../docs/reference/bilibili-helper-user-example.js)
(реальный предоставленный пример). В зависимости от структуры версии VOT
нужно:

1. Создать Helper нового сайта на основе существующих **новых** Helper-адаптеров
   этой же версии VOT, сохранив актуальные методы, возвращаемые поля и соглашения.
   Не копировать целиком старый Helper из другой версии.
2. Зарегистрировать Helper в фабрике/реестре Helpers VOT, подключить определение
   домена/сайта и необходимые селекторы плеера. Найти реальные файлы регистрации
   в своей версии форка: одного файла Helper недостаточно.
3. В `getVideoData()` получить канонический идентификатор и номер части,
   вызвать регистрацию на UMP (если сайт использует этот маршрут), проверить
   ответ `mediaUrl` и вернуть URL **UMP-медиа**, а не CDN-адрес или страницу.
4. Реализовать соответствующий серверный endpoint регистрации, если Helper
   его вызывает. В примере Bilibili это `POST /api/bilibili/register` с
   `{ bvid, page }`, ответ `{ mediaUrl }`; постоянный путь:
   `/media/bilibili/<BVID>/p<PAGE>/audio.m4a`.
5. Проверить, какой метод базового `VOTClient` вызывается для такого URL.
   В проверенном `@vot.js/core` `isCustomLink()` распознаёт `.m4a`, `.mpd`,
   `.m3u8` и ведёт в `translateVideoVOTImpl()` -> `requestVOT()` (JSON),
   **минуя** `VOTProtobufEnvelopeClient.request()`. Сервер UMP тогда пишет
   `[MEDIA MODE] Unsupported media request Content-Type: application/json`.
6. Для Bilibili исправление — переопределить `isCustomLink()` **в клиентском**
   `src/videoHandler/modules/protobufEnvelopeProvider.ts` так, как показано в
   [`docs/reference/protobufEnvelopeProvider.ts`](../docs/reference/protobufEnvelopeProvider.ts).
   Возвращать `false` только для подтверждённого URL Bilibili на доверенном
   UMP-хосте, а остальные URL передавать `super.isCustomLink(url)`.
   Для **нового сайта** добавляйте отдельное узкое правило только после
   проверки его маршрута, типа URL и протокола подписи.
7. Убедиться, что для этого сайта реально создан `VOTProtobufEnvelopeClient`
   и запрос проходит `request()` -> Protobuf Envelope с заголовком
   `application/x-vot-envelope+protobuf`. Выбор клиента проверять в
   `initVOTClient()` (или аналоге текущей версии VOT), не меняя глобально
   маршрутизацию Douyin и прямой `api.browser.yandex.ru`.
8. Проверить на практике регистрацию, HTTP Range, отправку перевода,
   звук/субтитры и отсутствие регрессий на существующих сайтах.

**Важно о подписанном запросе:** `sourceVideoUrl` внутри Envelope —
метаданные, а не замена URL в подписанном бинарном теле. Серверный адаптер
Bilibili принимает подписанный UMP URL и пересылает тело без переписывания.
Не пытайтесь «исправлять» JSON-запрос добавлением только `Content-Type`:
нужно выбрать правильную ветку клиента и передать настоящее бинарное тело.

**Ограничение примера:** `bilibili-helper-user-example.js` взят из конкретного
форка VOT и содержит жёстко заданный UMP-хост. При переносе в другую версию
проверьте API `BaseHelper`, механизм регистрации Helpers, разрешения GM XHR
и актуальную конфигурацию прокси. Это образец, а не универсальный модуль.
