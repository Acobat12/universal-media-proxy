# Адаптеры Universal Media Proxy (UMP)

Эта папка содержит серверные адаптеры для **Bilibili**, **Douyin** и **TikTok**. Они определяют, как UMP получает доступ к медиапотокам конкретной платформы и как распознаёт запросы перевода VOT.

> Это обновление **серверной части UMP**. Оно не является userscript и само по себе не добавляет поддержку сайта в клиент VOT: клиентскому helper также необходимо сформировать правильный запрос и, где требуется, зарегистрировать видео.

## Что реализовано

| Платформа | Регистрация | Медиаадрес | Особенности |
|---|---|---|---|
| Bilibili | `POST /api/bilibili/register` | `/media/bilibili/<bvid>/p<page>/audio.m4a` | Учитывается номер части `p`; DASH-аудио запрашивается через API Bilibili |
| Douyin | `POST /api/douyin/register` | Собственный маршрут Douyin | Регистрация хранится в памяти и после перезапуска требуется повторная регистрация |
| TikTok | `POST /api/tiktok/register` | `/media/tiktok/<videoId>/video.mp4` | Регистрация связывает ID и страницу; CDN разрешается сервером при обращении к видео |

Адреса `/media/...` являются стабильными адресами UMP, **не** прямыми CDN-ссылками. Сервер самостоятельно получает или обновляет исходные медиаадреса. Доступность конкретного ролика может зависеть от региона, авторизации и ограничений платформы.

## Установка и проверка

Поместите `bilibili.js`, `douyin.js` и `tiktok.js` в `src/adapters/` проекта UMP, предварительно сохранив резервные копии прежних файлов. Затем перезапустите Node.js и проверьте `GET /health` — там должен отображаться список загруженных адаптеров.

Загрузчик игнорирует скрытые файлы и файлы `.bak`. Синтаксическая или загрузочная ошибка адаптера останавливает запуск сервера, а не пропускается молча. Не копируйте README или `example.js` как обязательную часть работающего сервера: пример служит документацией.

## Как добавить новый сайт

Создайте `src/adapters/newsite.js` по образцу `example.js` из этого архива. Минимальный адаптер содержит:

- `id` — уникальное имя сайта;
- `matches(url)` — точное распознавание поддерживаемых страниц;
- `resolve(url, context)` — получение **настоящих** HTTPS-ссылок на медиа;
- `mediaHosts` — доверенные CDN-домены, на которые разрешены обращения.

**Пример не является готовым интеграционным модулем:** в нём специально оставлена функция `getRealMediaUrl()`, которую нужно реализовать для API конкретного сайта. Возвращать вымышленный CDN-адрес нельзя.

`POST /api/resolve` использует зарегистрированные адаптеры. При необходимости добавьте `stableMediaPath()` и `resolveMediaPath()` для постоянных путей `/media/<site>/...`. Эти методы **не** создают регистрацию автоматически. Если нужен `POST /api/<site>/register`, его обработчик необходимо реализовать отдельно, например через `handleRequest()`.

### Перевод VOT

#### Четыре поля protobuf-запроса

Клиент VOT передаёт серверу **protobuf-конверт с четырьмя полями**. Это поля конверта, а не четыре URL или четыре аргумента функции:

| Поле | Содержимое | Назначение |
|---|---|---|
| **1** | HTTP-заголовки запроса (`headers`) | Передают необходимые заголовки в виде повторяющихся записей «имя — значение». |
| **2** | Тело запроса (`body`) | Исходные бинарные данные запроса перевода, включая данные, связанные с подписью. |
| **3** | Путь или URL назначения | В обычном режиме — путь `/video-translation/translate`; в режиме UMP для поддерживаемого сайта — **будущий стабильный URL медиа на UMP**. |
| **4** | URL исходной страницы видео | Позволяет серверной части определить исходный сайт и получить из него реальную ссылку на скачивание или медиапоток. Используется в соответствующем режиме интеграции; в обычном конверте может отсутствовать. |

**Подробно о полях 3 и 4**

**Поле 3 — будущая ссылка на UMP.** Например, `https://media-proxy.freedynamicdns.org/media/tiktok/123456789/video.mp4`. Это заранее сформированный адрес, по которому сервер перевода впоследствии запросит медиа. **Это не исходная CDN-ссылка.** Чтобы адрес работал, UMP должен уметь обслужить соответствующий `/media/...` маршрут, а при необходимости видео должно быть предварительно зарегистрировано.

**Поле 4 — ссылка на оригинальный сайт.** Например, `https://www.tiktok.com/@author/video/123456789`. Она передаётся серверу как источник, по которому можно определить видео и найти действительный CDN-адрес для скачивания. **Это не URL UMP и не готовая ссылка на CDN.** Получение реального CDN-адреса — задача серверного адаптера.

Схема: `helper → регистрация (если обязательна) → protobuf (поле 3: UMP URL; поле 4: исходная страница) → сервер перевода → UMP → CDN`.

**Совместимость:** не подменяйте поле 3 на UMP-адрес для всех сайтов безусловно. Для старого маршрута перевода оно остаётся `/video-translation/translate`; поле 4 в таком случае не обязательно. Конкретная поддержка полей 3 и 4 должна соответствовать реализации клиента и серверного адаптера.

Для поддержки серверного режима перевода адаптер может реализовать `prepareMediaTranslation(body, { publicBaseUrl })`.

- Если подписанный protobuf относится к **другому** сайту, верните `null`.
- Если запрос распознан и корректен, верните `{ body, mediaUrl }`.
- Если запрос однозначно относится к этому сайту, но некорректен, выбросьте ошибку.
- Не изменяйте подписанные байты `body`, если протокол подписи этого не допускает.

Диспетчер проверяет адаптеры в порядке убывания `mediaTranslationPriority` (по умолчанию `0`). В существующих Bilibili, Douyin и TikTok реализована соответствующая проверка URL из подписанного protobuf. **Новый адаптер без `prepareMediaTranslation()` не начнёт автоматически обслуживать VOT.**

### Постоянные пути и регистрация

`stableMediaPath(url, context)` возвращает предсказуемый путь на UMP, построенный из проверенного идентификатора видео. `resolveMediaPath(path, context)` проверяет **весь** путь и заново определяет реальный источник. Не сохраняйте в постоянном пути токены, cookie или временные CDN-ссылки.

Регистрация используется там, где нужно заранее связать идентификатор видео с исходной страницей или дополнительным контекстом. В частности, TikTok требует регистрации перед использованием `/media/tiktok/<videoId>/video.mp4`.

## Безопасность и ограничения

`mediaHosts` задаётся списком доверенных CDN-доменов без схемы и пути. Дополнительно UMP проверяет HTTPS и DNS-адреса, чтобы не допускать обращений к внутренним сетям. Список разрешённых upstream-хостов также может задаваться через `ALLOWED_UPSTREAM_HOSTS` — учитывайте конфигурацию своей версии UMP.

Не принимайте произвольные URL CDN, cookie или заголовки авторизации от клиентов без отдельной проверки. Не пытайтесь обходить DRM или авторизацию. Для некоторых сайтов потребуется отдельная логика получения CDN-ссылок, работа с временными токенами и обработка ошибок API.

## Отладка

Если перевод не запускается, последовательно проверьте загрузку адаптера в `/health`, успешность регистрации (если она предусмотрена), правильность пути `/media/...`, наличие реального upstream и распознавание подписанного URL в `prepareMediaTranslation()`. Сообщение `No adapter can prepare this media translation` обычно означает, что ни один адаптер не принял данный запрос; это не обязательно проблема CDN.
